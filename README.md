 О проекте

В рамках проекта реализована система классов, описывающая поведение кошачьих. Приложение демонстрирует применение принципов **чистой архитектуры**, **инъекции зависимостей (Dependency Injection)** и **Test-Driven Development (TDD).

Основные задачи спринта:
*   Реализация бизнес-логики классов `Feline`, `Cat` и `Lion`.
*   Развязывание зависимостей (класс `Lion` и `Cat` не должны создавать `Feline` самостоятельно).
*   Написание юнит-тестов с покрытием **100%** (JaCoCo).
*   Настройка автоматического тестирования (GitHub Actions).

## 🏗 Архитектура

Проект разделен на три логических пакета в соответствии с Single Responsibility Principle:

| Пакет | Класс | Описание |
| :--- | :--- | :--- |
| `com.example.feline` | **Feline** | Базовый класс. Хранит общие атрибуты (пол, возраст, наличие гривы) и базовые действия (издает звук, ест мясо). |
| `com.example.cat` | **Cat** | Домашняя кошка. Использует `Feline` для базовых нужд, но имеет собственное имя и логику сообщения о котятах. |
| `com.example.lion` | **Lion** | Лев. Использует `Feline` для получения еды и информации о котятах. Самостоятельно определяет рацион в зависимости от пола (`Самец` ест копытных, `Самка` — травоядных). |

### Инъекция зависимостей
Классы `Cat` и `Lion` получают объект `Feline` через конструктор. Это позволяет:
1.  Легко подменять реальный `Feline` на **Mock** в тестах.
2.  Изолировать юнит-тесты от реализации базовых классов.
3.  Проверять только логику конкретного класса (например, ветвление `if-else` в `Lion.getFood()`).
